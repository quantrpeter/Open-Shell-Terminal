# Plan: Open Shell Terminal

A standalone GUI terminal for Open Shell on Windows, Linux and macOS. Commands run in the Open Shell engine and their JSON records show as tables, with a file explorer on the left where clicking a folder runs `cd`.

## Stack

- Electron, React, TypeScript, Vite (electron-vite). Zustand for state, TanStack Virtual for the tree and tables, Allotment for splits, cmdk for the palette.
- The engine is `openshell.py --rpc`: newline-delimited JSON-RPC over stdin and stdout, one Python process per pane. No network port.
- Packaged builds ship their own CPython (python-build-standalone) plus `openshell.py` and `command/`. PyInstaller is not used: freezing drops stdlib modules that user and registry command files import.

## Layout

- Left: explorer tree rooted at a pinned folder (home by default), following the active pane's cwd. Click a folder to `cd`, chevron to expand, right-click for open in tab or split, insert path, copy path, reveal, set as root. Drag rows into the prompt.
- Centre: tabs, split panes, one block per command (table, command output lines, text, JSON, error), prompt with Tab completion and history.
- Right (toggle): preview of the clicked file (text, JSON, image).
- Bottom: status bar. Top right: split and palette buttons. Palette: Ctrl/Cmd+Shift+P.

## Why one engine per pane

The shell keeps its cwd, `$PWD` and pipeline index in process globals. A process per pane gives each pane its own cwd, lets panes run at once, and makes hard cancel safe: soft cancel first (checked between records and while an external program is silent), then the process tree is killed and respawned in the same directory after 1.5 s.

## Known limits

- Interactive programs (`vim`, `ssh`) do not work; `ext` programs get no stdin.
- Sorting and filtering happen in the renderer over the rows received so far.
- Programs on PATH are not commands. Run them with `ext PROGRAM [ARGS]`. A pipeline cannot pipe records into `ext`; it must start the pipeline.
- Command packages that need pip modules (for example `cryptography`) fail to load in a packaged build, because the bundled Python has only the standard library. A per-user site-packages folder for the engine is needed.
- A packaged app started from Finder has a minimal PATH, so programs installed by Homebrew are not found until the login-shell PATH is imported.
